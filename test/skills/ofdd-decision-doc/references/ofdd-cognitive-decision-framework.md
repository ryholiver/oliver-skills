# OFDD 认知决策框架

> 版本：v5 · 2026-08-19  
> 范围：定义 Observation、Finding、Direction、Decision 及其证据追溯规则。  
> 不包含：决定后的计划、执行和验收规则，相关内容见 [决定执行与反馈闭环](./决定执行与反馈闭环.md)。

---

## 一、框架目标

OFDD 用于约束人和 AI 从来源材料形成决定的过程：

```text
Observation → Finding → Direction → Decision
```

它不是要求所有信息机械地经过四层，而是为不同性质的内容提供清晰位置，防止事实、解释、评价、行动倾向和正式决定混写。

---

## 二、实体

### 2.1 核心实体

| 实体 | 定义 | 回答的问题 | 关键约束 |
| --- | --- | --- | --- |
| **来源 Source** | 承载原始内容的材料或可定位事件 | 内容来自哪里？ | 必须可定位到文件、链接、人员、时间或事件 |
| **证据引用 Evidence Reference** | 指向来源中特定证据片段的稳定引用 | 观察具体依据来源中的哪一段？ | 必须有独立 ID、来源 ID 和位置；关键证据宜有稳定锚点 |
| **观察 Observation** | 对证据内容或可直接感知事件的忠实记录 | 证据中记录了什么？ | 不引申；必须引用证据；不因来源权威而自动视为客观真相 |
| **发现 Finding** | 建立在观察之上的认知产物 | 观察之外获得了什么？ | 必须声明类型、状态和依据 |
| **方向 Direction** | 基于发现或明确外部指令形成的行动指向 | 接下来值得往哪里走？ | 说明目标和依据；不等于已拍板 |
| **决定 Decision** | 对一个或多个方向作出的正式取舍 | 最终选择、拒绝或暂缓什么？ | 说明依据、状态、适用范围、未决项和重评条件 |

### 2.2 证据引用的数据结构

证据引用是来源与观察之间的定位层。来源表示整份材料，证据引用表示材料中支撑某条观察的具体片段。

```text
观察 → 引用 → 证据引用 → 位于 → 来源
```

| 字段 | 必填 | 说明 | 示例 |
| --- | --- | --- | --- |
| `id` | 是 | 稳定机器标识，不承担显示职责 | `E-009` |
| `source_id` | 是 | 所属来源 ID | `S-04` |
| `label` | 是 | 人类可读的显示名称 | `张敏访谈：真实约课渠道` |
| `locator` | 是 | 行号、时间戳、页码或事件时间 | `L58/L70` |
| `anchor` | 否 | 不随行号变化的稳定定位符 | `src-zm-primary-channel` |
| `quote_snapshot` | 否 | 从来源复制的短原文快照，不得改写 | `也有微信，比较偏电话快一些。` |
| `context_summary` | 否 | 对证据上下文的概括，必须标明不是原文 | `张敏说明电话是主要约课渠道` |
| `integrity` | 是 | 定位与快照的完整性状态 | `完整 / 待补位置 / 待加锚点 / 已漂移` |

编号、显示与内容各自承担不同职责：

- ID 用于机器关联，原则上保持不变；
- label 用于 Markdown 或 HTML 默认展示；
- quote_snapshot 用于鼠标悬停、证据卡片或人工核对；
- source_id 与 anchor 用于点击跳转到完整上下文；
- locator 用于没有锚点时的人工兜底。

`quote_snapshot` 是引用时的原文快照，不是新的事实来源。若当前来源内容与快照不一致，应标记为“已漂移”并重新校准，不得无声覆盖。

### 2.3 发现的子类型

| 子类型 | 定义 | 典型问题 | 必填信息 |
| --- | --- | --- | --- |
| **推断 Inference** | 从观察中得到的描述性、解释性、因果性或预测性信息 | 事实可能说明了什么？ | 观察依据、推断内容、验证方式、状态 |
| **判断 Judgment** | 依据目标或标准，对观察或推断作出的评价性结论 | 这对目标意味着什么？ | 评价对象、评价标准、依据、判断结果、状态 |
| **疑问 Question** | 由观察、推断或判断触发、需要进一步回答的问题 | 还缺少什么答案？ | 触发依据、验证方式、阻塞性、状态 |

### 2.4 判断与相邻概念的边界

| 概念 | 示例 | 边界 |
| --- | --- | --- |
| 证据引用 | 张敏访谈 L58/L70 的原文片段 | 定位到来源中的具体内容 |
| 观察 | 张敏表示真实约课主要通过电话进行 | 忠实记录证据内容 |
| 推断 | 当前企微方案可能没有覆盖主要约课渠道 | 描述事实之间可能存在的关系 |
| 判断 | 若目标是覆盖真实主流程，当前方案存在范围错配风险 | 使用目标或标准进行评价 |
| 方向 | 先确认 AI 实际接管的流程段和渠道 | 给出行动指向，但尚未拍板 |
| 决定 | Review 前不扩大开发范围，先完成边界确认 | 对方向作出正式取舍和承诺 |

判断可以具有行动倾向，但不得直接写成行动指令。判断回答“是否匹配、是否重要、风险多大”，方向回答“接下来往哪里走”。

## 三、状态

不同类型不能机械共用一套状态。

### 3.1 推断与判断状态

| 状态 | 含义 |
| --- | --- |
| **待验证 Pending** | 尚未执行验证 |
| **已支持 Supported** | 当前证据支持，但允许被新证据修正 |
| **已推翻 Refuted** | 已获得足以否定该内容的证据 |
| **证据不足 Inconclusive** | 已验证，但现有证据不足以下结论 |
| **证据冲突 Conflicted** | 存在互相冲突且尚未消解的证据 |

### 3.2 疑问状态

| 状态 | 含义 |
| --- | --- |
| **待回答 Open** | 尚未获得答案 |
| **已回答 Answered** | 已获得可用于后续认知或行动的答案 |
| **暂缓 Deferred** | 当前不处理，但保留触发条件 |
| **无法回答 Unanswerable** | 当前条件下无法取得所需证据 |
| **作废 Cancelled** | 前提变化后，该疑问不再成立 |

### 3.3 方向状态

| 状态 | 含义 |
| --- | --- |
| **探索中 Exploring** | 正在补充依据或明确范围 |
| **待决策 Awaiting Decision** | 方向已经具备进入取舍的基本条件 |
| **已进入决策 In Decision** | 已被一个拟议或已拍板决定选择、拒绝或暂缓 |

### 3.4 决定状态

| 状态 | 含义 |
| --- | --- |
| **拟议 Proposed** | 已提出但尚未拍板 |
| **已拍板 Approved** | 已正式生效 |
| **已撤销 Revoked** | 决定被明确取消 |
| **已替代 Superseded** | 已被新决定取代，必须链接替代决定 |

## 四、关系

| 关系 | 主体 → 客体 | 说明 |
| --- | --- | --- |
| **位于 located_in** | 证据引用 → 来源 | 每条证据引用必须属于一个来源 |
| **定位到 points_to** | 证据引用 → 来源位置/锚点 | 指向行号、时间戳、页码或稳定锚点 |
| **引用 cites** | 观察 → 证据引用 | 每条观察至少引用一条可定位证据 |
| **基于 based_on** | 推断 → 观察 | 推断必须能回溯到观察 |
| **评价 evaluates** | 判断 → 对象 | 声明被评价的方案、流程、目标或状态 |
| **采用标准 uses_criterion** | 判断 → 评价标准 | 声明形成判断所使用的目标或标准 |
| **依据 supported_by** | 判断 → 观察/推断 | 判断可以直接依据观察，也可以依据推断 |
| **触发 raises** | 观察/推断/判断 → 疑问 | 说明疑问为什么产生 |
| **驱动 driven_by** | 方向 → 发现 | 方向由推断、判断或疑问驱动 |
| **源于指令 mandated_by** | 方向 → 观察 | 外部明确交办可直接形成方向，但交办本身须先作为观察记录 |
| **选择 selects** | 决定 → 方向 | 决定正式选择某条方向 |
| **拒绝 rejects** | 决定 → 方向 | 决定明确不采用某条方向 |
| **暂缓 defers** | 决定 → 方向 | 决定暂不采用并记录重评条件 |
| **存在未决项 has_open_question** | 决定 → 疑问 | 记录决定尚未解决的问题 |
| **替代 supersedes** | 新决定 → 旧决定 | 保留决定变更历史 |

完整主链通常为：

```text
决定 → 方向 → 发现 → 观察 → 证据引用 → 来源
```

外部明确交办形成方向时，可以使用：

```text
决定 → 方向 → 观察（交办记录）→ 证据引用 → 来源
```

## 五、规则

### 5.1 来源、证据引用与观察规则

1. 来源表示整份材料；证据引用表示材料中支撑观察的具体片段，二者不得混用。
2. 每条证据引用必须有稳定 ID、来源 ID、显示名称和可解释的位置标识。
3. 每条观察至少引用一条证据引用；只写来源文件而没有具体位置的观察，来源完整性不足。
4. 关键观察宜使用稳定锚点；行号、时间戳或页码作为辅助定位与人工兜底。
5. `quote_snapshot` 如存在，必须从来源逐字复制，不得把概括伪装成引语。
6. 来源内容与原文快照不一致时，证据引用标记为“已漂移”，完成校准前不得无声更新观察。
7. 同一证据片段被多条观察引用时，应复用同一个证据 ID，不重复复制来源内容。
8. 观察只承诺证据中存在该内容，不自动承诺来源内容客观正确。
9. 观察中不得混入解释、风险评价或行动建议。
10. HTML、Obsidian、GitHub 等工具可以采用不同链接语法，但不得改变底层的来源 ID、证据 ID 和追溯关系。

### 5.2 推断规则

11. 推断必须声明基于哪些观察。
12. 推断必须能够被证据支持、推翻或判定为证据不足。
13. 推断描述“是什么、为什么、可能发生什么”，不得直接写成行动指令。
14. 多个来源口径一致可以提高支持程度，但不自动等同于客观真相。

### 5.3 判断规则

15. 判断必须声明评价对象和评价标准。
16. 判断必须基于观察或推断，不得只凭未说明的个人偏好。
17. “重要、合理、风险高、价值大、优先”等评价词必须说明相对于什么目标或标准。
18. 判断可以驱动方向，但判断本身不得冒充方向或决定。

### 5.4 疑问规则

19. 疑问必须说明由哪条观察、推断或判断触发。
20. 疑问必须标记是否阻塞方向、决定、计划或执行。
21. 疑问被回答后，答案应形成新的证据引用和观察；必要时再产生新的推断或判断，不直接把疑问改写成结论。

### 5.5 方向规则

22. 每个方向必须声明目标和依据。
23. 方向通常由发现驱动；明确的外部交办也可以形成方向，但交办内容必须先作为观察记录。
24. 方向只表示值得探索或采取的行动指向，不代表已经获得资源或正式批准。
25. 同一组发现可以产生多个互斥或并行方向。

### 5.6 决定规则

26. 决定必须明确选择、拒绝或暂缓哪些方向，不使用无对象的“做”或“不做”。
27. 决定至少记录：状态、依据、适用范围、未决项、未决项阻塞性、重新评估条件。
28. 已拍板决定可以保留非阻塞性未决项；存在阻塞性未决项时，不得进入相应执行阶段。
29. 决定变更不得覆盖历史，必须标记为撤销或已替代，并链接新决定。
30. 决定“不做”也必须记录原因与重新评估条件。

### 5.7 更新、追溯与展示规则

31. 新内容按时间追加，不无声覆盖历史。
32. 状态变化必须记录日期、触发证据和变更原因。
33. AI 产出时必须区分“来源原文”“证据引用”“观察概括”“推断”“判断”“方向”和“决定”。
34. 前端默认展示 label，不要求向普通用户暴露裸 ID；审计或调试视图可以显示完整编号。
35. HTML 悬停内容优先读取证据引用的 `quote_snapshot` 或根据 `source_id + anchor` 动态提取，点击跳转使用来源与锚点。
36. 示例不得省略正式规则要求的关键字段，避免 AI 模仿错误的简写。

## 七、完整示例

```text
来源 S-004：
标题：张敏访谈：AI 约课流程与关键指标讨论。
文件：01-事实性资料/2026-08-18_销售张敏访谈_AI约课流程与关键指标讨论_原文.md。

证据引用 E-009：
来源 ID：S-004。
显示名称：张敏访谈：真实约课渠道。
位置：L58/L70。
稳定锚点：src-zm-primary-channel（待写入来源文件）。
原文快照：“也有微信，比较偏电话快一些。”
完整性：待加锚点。

观察 O-001：
张敏表示约课渠道包括微信，但更偏向电话，并主张优先打电话。
证据引用：E-009。

证据引用 E-015：
来源 ID：S-005。
显示名称：销售 AI 约课机器人项目：企微承接范围。
位置：项目合同相关条目，待补精确锚点。
完整性：待补位置。

观察 O-002：
当前项目文档包含通过企微承接真实线索并形成可追踪链路的要求。
证据引用：E-015。

推断 F-I-001（待验证）：
当前方案覆盖的交互渠道可能与销售主要约课渠道不完全一致。
基于：O-001、O-002。

判断 F-J-001（待验证）：
评价对象：当前企微优先方案。
评价标准：是否覆盖真实约课主流程。
判断结果：当前方案可能存在范围错配风险。
依据：F-I-001。

疑问 F-Q-001（待回答，阻塞决定）：
AI 约课在 Q3 实际接管销售流程的哪一段、哪些渠道？
触发依据：F-J-001。

方向 DIR-001：
在扩大开发范围前，先确认接管流程段、渠道与 Q3 验收边界。
依据：F-J-001、F-Q-001。

决定 DEC-001（示例）：
决定动作：选择 DIR-001。
状态：拟议。
未决项：Q3 验收边界。
重新评估条件：负责人 Review 完成并形成可定位记录。
```

未来 HTML 可以将 `E-009` 渲染为“张敏访谈：真实约课渠道”，鼠标悬停展示原文快照，点击后通过来源文件与稳定锚点打开完整上下文。ID 继续作为内部关联，不要求直接显示给普通用户。
