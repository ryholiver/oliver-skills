# OFDD 证据驱动工作系统

> 版本：v5 · 2026-08-19  
> 用途：规定人和 AI 如何从原始材料形成可追溯的认知、方向、决定，并将决定连接到执行反馈。  
> 定位：这是一套工作认知与决策元模型，不是具体业务领域本体。

---

## 一、系统由两个框架组成

### 框架 A：OFDD 认知决策框架

```text
Observation → Finding → Direction → Decision
观察 → 发现 → 方向 → 决定
```

OFDD 负责回答：

1. 来源中实际记录了什么？
2. 从观察中获得了什么新信息、评价或疑问？
3. 接下来值得往哪个方向行动？
4. 最终选择、拒绝或暂缓哪条方向？

其中，发现包含三种认知产物：

```text
Finding
├── Inference  推断：事实可能说明了什么
├── Judgment   判断：这对目标意味着什么
└── Question   疑问：还需要回答什么
```

详细定义与规则见：[OFDD认知决策框架](./OFDD认知决策框架.md)。

### 框架 B：决定执行与反馈闭环

```text
Decision → Plan → Action → New Observation
决定 → 计划 → 执行 → 新观察
```

执行闭环负责回答：

1. 如何把已拍板决定转化为可执行计划？
2. 执行前需要满足哪些前置条件？
3. 如何验证执行结果？
4. 如何把结果重新送回下一轮 OFDD？

详细定义与规则见：[决定执行与反馈闭环](./决定执行与反馈闭环.md)。

## 二、两个框架的接口

两个框架概念上分离，但通过以下接口连接：

| 接口 | 含义 | 约束 |
| --- | --- | --- |
| 决定 → 计划 | 将认知决策转化为执行安排 | 只有已拍板且无阻塞性未决项的决定才能进入执行计划 |
| 执行 → 新观察 | 将执行结果转化为下一轮证据 | 结果必须忠实记录，不得因符合或不符合预期而选择性省略 |
| 执行异常 → OFDD | 当前提、范围或判断失效时回到认知决策 | 不允许只修改计划来掩盖上游假设错误 |

完整循环：

```text
来源 → 证据引用 → 观察 → 发现 → 方向 → 决定
                   ↑                      ↓
                 新观察 ← 执行 ← 计划 ←──┘
```

这不是要求每条观察都必须走到执行。观察可以仅作为背景；发现可以暂不形成方向；方向可以被拒绝或暂缓；决定“不做”也可以作为有效结果。

## 四、与相关方法论的关系

OFDD 可借鉴 DIKW 和 OODA，但不与其逐项等同：

- DIKW 用于理解从材料到认知价值的提升；
- OODA 用于理解观察、定向、决策与行动循环；
- OFDD 的独特重点是区分观察、推断、判断、方向和决定，并保持证据追溯。

## 五、使用原则

1. 先判断当前内容属于认知决策，还是决定后的执行安排。
2. 事实记录、推断、判断、方向和决定必须分开表达。
3. 来源表示整份材料，证据引用定位具体片段；来源证明“有人说过或材料写过什么”，不自动证明该说法客观正确。
4. 判断必须声明评价对象和评价标准，避免隐含价值标准。
5. 方向不等于决定；决定必须明确选择、拒绝或暂缓什么。
6. 计划不是 Todo 的同义词；Todo 是计划的执行视图。
7. 证据编号用于稳定关联；前端可显示可读名称，并通过悬停展示原文快照。
8. 所有状态变化追加记录，不无声覆盖历史。
